## Что сделано

### Проекты
- Компактные двухуровневые карточки: название (1 строка) + описание (≤2 строки) + меню `⋮`.
- Низ: открытые / выполненные / % + полоса прогресса; 0 задач → 0% (без деления на ноль).
- Действия перенесены в меню: активный — «Изменить», «В архив», «Удалить»; архивный — «Изменить», «Вернуть», «Удалить».
- Подтверждение удаления сохранено; архивные визуально приглушены; архив/возврат без дублей.

### Задачи
- Сворачиваемые группы по UUID проекта + группа «Без проекта».
- Старт до первой настройки: «Без проекта» и первая проектная группа раскрыты; далее — сохранённое локальное состояние.
- Меню «Без проекта»: «Закрепить наверху» / «Вернуть вниз» (только локально).
- Поиск и фильтры глобальные; пустые после фильтрации группы скрыты; счётчик в заголовке = видимые задачи.
- Сортировка внутри группы (только UI): открытые просроченные → срок ASC (null в конце) → приоритет DESC → `updatedAt` DESC → `id`.

### Круг выполнения
- Отдельный `TaskDoneToggle` (≥ 44 dp): только смена статуса, без открытия карточки.
- Основная область строки (название, описание, свободное место) — только открытие деталей.
- При `onToggleDone != null` — некликабельный `Surface` + две независимые зоны (кликабельный `Surface(onClick)` в этом режиме не используется).
- Путь сохранения единственный: `TaskDoneToggle` → `TasksScreen` → `AppViewModel.changeStatus` → `PlannerRepository.setTaskStatus` → `saveTask`.
- Защита: `pendingToggleKeys` по стабильному `syncUuid` (снятие в `finally`) + debounce 500 мс на монотонных часах (`SystemClock.elapsedRealtime`).

## Ручная приёмка (Redmi Note 10 Pro, 11.09.2026)

1. APK установился обновлением поверх существующей версии; удаление приложения не потребовалось.
2. Пользовательские данные, проекты и сопряжение с Rubezh сохранились.
3. На экране проектов видны четыре полные компактные карточки и начало пятой.
4. Меню активного / архивного проекта соответствует требованиям (Изменить / В архив|Вернуть / Удалить).
5. Архивирование и возврат проекта работают без дублей.
6. Группы задач раскрываются и сворачиваются по заголовку; состояние и pin «Без проекта» сохраняются после перезапуска; самостоятельного раскрытия групп нет.
7. Круг меняет статус и не открывает задачу; текст открывает задачу и не меняет статус.
8. После corr2 двойное и тройное быстрое нажатие дают одно изменение статуса.
9. На чистой очереди: 0 → одно нажатие круга → ровно 1 исходящая операция → успешная передача в Rubezh → корректный статус на ПК.
10. Тестовая задача удалена; после двусторонней синхронизации итог: 12 активных проектов, 0 архивных, 114 задач (107 открытых / 7 завершённых), очереди пусты, открытых конфликтов нет.

### Наблюдение по ранее накопленной очереди (контроль, без пользовательских текстов)

- На телефоне обнаруживалась очередь из 88 операций; эксперимент — только после проверенной резервной копии Rubezh.
- Пакет затрагивал два UUID: 86 операций одной тестовой задачи (1 create + 85 update статуса) и 2 update одного проекта (архив / возврат).
- Исходы: 1 создана, 83 применены как изменения, 2 skipped как уже совпадающие, 2 конфликта по одному проекту, удалений не было; остальные сущности не изменены.
- Конфликты разрешены сохранением версии ПК; откат резервной копии не потребовался.
- На исправленной сборке повторная чистая проверка: одно принятое нажатие → ровно одна sync-операция.
- Физическое происхождение всех 85 старых нажатий по истории не доказывается; подтверждены состав пакета и отсутствие массового изменения прочих данных.

### Остаточное наблюдение (Rubezh UI, вне объёма части 1)

После удаления тестовой задачи исходящая операция на ПК создавалась, а счётчик «ожидают отправки» обновлялся только после перезапуска Rubezh; затем удаление успешно передалось. Причина в Rubezh не исследовалась и не исправлялась; приёмку мобильной части 1 это не блокирует.
