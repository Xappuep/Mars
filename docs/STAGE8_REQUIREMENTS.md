## 1. Область этапа

1. Перевести телефонное приложение на доменную модель «Рубежа»: **проекты** и **задачи** с двумя статусами.
2. Реализовать двусторонний обмен телефон ↔ ПК по локальной сети: сопряжение по QR, отправка и приём пакетов операций, разбор расхождений.
3. Перенести данные Mars 1.x без потерь и без ручных действий пользователя.
4. Обеспечить безопасность канала и секретов сопряжения.
5. Привести визуальную часть к темам «Рубежа».

Вне области этапа: облачные аккаунты, обмен между несколькими телефонами, публикация release-сборки.

## 2. Требования к доменной модели

- **Проект** (`project`): `sync_uuid`, `name`, `description`, `archived`, `created_at`.
  Реализация: `domain/model/Models.kt` (`ProjectItem`), таблица `projects`.
- **Задача** (`task`): `sync_uuid`, `title`, `description`, `project_uuid`, `priority`, `due_at`, `status`, `created_at`.
  Реализация: `domain/model/Models.kt` (`TaskItem`), таблица `tasks`.
- Статусы задачи — ровно два: `open` («Открыта») и `done` («Выполнено»); см. `TaskStatus` в `domain/model/Enums.kt`.
- Приоритеты: `low`, `normal`, `high` (`TaskPriority`).
- Срок задачи хранится как **метка времени** (`dueAtEpochMillis`), не как дата + опциональное время.
- Подзадач, вложенности и отдельной сущности «дополнение» в модели **нет**: старые данные превращаются в обычные задачи (правила — в `docs/STAGE8_MIGRATION.md`).
- Демонстрационные записи помечены флагом `isDemo` и в обмен с ПК не попадают.

## 3. Требования к переносу данных 1.x

Обязательны к исполнению правила из `docs/STAGE8_MIGRATION.md`:
категории → проекты, подзадачи и дополнения → задачи с пометкой в описании,
`NEW`/`IN_PROGRESS`/`POSTPONED`/`NOT_DONE` → `open`, `DONE`/`CANCELLED` → `done`,
дата без времени → `23:59` местного времени, демо исключается из обмена,
всем сущностям назначается UUID, старые таблицы сохраняются во внутреннем архиве.

Дополнительно:

- миграция выполняется одной транзакцией Room, повторный запуск невозможен;
- пользователь получает однократный отчёт о переносе (диалог «Данные перенесены в новую модель»);
- архив старых данных можно выгрузить из Настроек.

## 4. Требования к синхронизации

- Протокол `rubezh-sync` версии **1**; несовпадение версии — отказ с кодом `unsupported_protocol`.
- Транспорт: **HTTPS** в локальной сети, сертификат ПК закреплён по SHA-256 из QR-кода.
- Сопряжение: QR с ПК → заявка → подтверждение человеком на ПК → выдача `device_id` и `device_token`.
- Обмен единицами журнала: операции `create` / `update` / `delete` по сущностям `project` / `task`.
- Версионирование записей: SHA-256 канонического JSON (`version_hash`), совместимый с `rubezh.sync.protocol`.
- Порядок применения внутри пакета — причинный: проект применяется до ссылающейся на него задачи.
- Повторная отправка того же набора операций идемпотентна (детерминированный `package_id`).
- Повторное применение пакета с тем же `package_id` не дублирует данные.
- Конфликт (запись изменена и на телефоне, и на ПК) **не затирает** локальные данные, а попадает в журнал расхождений; выбор делает пользователь.
- Отказ любой проверки пакета откатывает весь пакет.
- Предел размера тела запроса и ответа — 1 MiB; исходящий пакет обрезается по зависимостям.

Реализация: `sync/RubezhSyncClient.kt`, `sync/PackageEngine.kt`, `sync/VersionHash.kt`,
`sync/SyncCoordinator.kt`, `sync/TlsFingerprint.kt`, `sync/SecureTokenStore.kt`.
Подробности — в `docs/STAGE8_SYNC_IMPLEMENTATION.md`.

## 5. Требования к безопасности

- `device_token` — только в хранилище под ключом Android Keystore, вне DataStore и вне резервных копий.
- Незашифрованный трафик запрещён на уровне конфигурации сети приложения.
- Токены и отпечатки не попадают в логи и не показываются на экране.
- Отпечаток сертификата проверяется **до** отправки одноразового токена сопряжения.

Подробности — в `docs/STAGE8_SECURITY.md`.

## 6. Требования к интерфейсу

- Экран **«Проекты»** со списком проектов, архивом и переходом к задачам проекта.
- Экран **«Синхронизация с ПК»**: состояние сопряжения, счётчик «К отправке», счётчик расхождений, метки последней отправки и приёма, кнопки «Сканировать QR с ПК», «Отправить», «Получить с ПК», «Проверить связь», «Разорвать сопряжение».
- Экран **«Расхождения»**: обе версии записи и выбор «Оставить телефон» / «Принять ПК».
- Экран **«Инструкция»** с пошаговым описанием сопряжения.
- **Семь тем «Рубежа»**: `orbit`, `nebula`, `white-station`, `ash-amber`, `polar-night`, `light-concrete`, `shelter-terminal`; регулятор интенсивности эффектов и режим уменьшения анимаций.
- Все тексты интерфейса — на русском языке, без технических кодов в основных сообщениях.

## 8. Критерии готовности этапа

1. `gradlew.bat test` проходит полностью.
2. `gradlew.bat assembleDebug` собирает APK.
3. Перенос данных 1.x выполняется по правилам раздела 3 и подтверждается отчётом.
4. Обмен с ПК проходит полный цикл: сопряжение → отправка → приём → разбор расхождения.
5. Секреты сопряжения не обнаруживаются в открытом виде в настройках, логах и резервных копиях.

Пункты 1 и 2 выполнены. Пункты 3–5 требуют ручной приёмки на реальном ПК с «Рубежом».
